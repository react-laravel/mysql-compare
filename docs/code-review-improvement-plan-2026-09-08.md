## 2. 实施顺序

### 第一阶段：修复会导致结果失真或执行不符的问题

1. **同步计划绑定**
   - 引入不可变请求快照和 fingerprint，表选择、端点、策略或开关改变即失效。
   - 预览请求具有版本号、加载态和错误态；执行只接受对应计划的 snapshot。
   - 后端保存短期 `planId`，记录请求与结构 fingerprint；执行前检查结构是否变化、表是否可读、源目标是否指向同一对象、目标是否支持该动作。
   - 表预检失败时在破坏性语句之前返回。按引擎和操作报告已经完成的步骤；MySQL DDL 不承诺整体回滚。
2. **类型与比较语义**
   - 定义前后端一致的类型化值协议和主键编码；精确整数/小数保留字符串精度，二进制具有独立类型。
   - 文本默认逐值比较，只有字段元数据允许时才规范化日期或数值；不能用显示格式作为比较值。
   - 完整复合主键参与配对。缺少可用唯一键或发现重复键时，给出不可可靠对比状态，不能覆盖 Map 项后继续宣称准确。
   - 用统一比较会话返回两侧已对齐行；过渡期间，尚未核实缺失的行必须显示“待核实”。
3. **导入、导出和引擎能力**
   - 所有范围选项由后端执行，明确 all / filtered / page / selected 的参数规则。
   - 结构和数据分别按目标方言编码；PostgreSQL 的占位 DDL 不能作为可执行 SQL。
   - 定义能力表，由后端校验并供 UI 禁用未支持的组合。优先完成同引擎流程；跨引擎数据同步要求目标表及字段映射可验证，跨引擎结构同步不默认开放。
   - CSV 使用完整记录解析，支持引号、转义、换行、CRLF 和 BOM；区分空字符串与 NULL 的导入策略。

验收：复现上述误判的测试先失败，修改后通过；改变同步策略必须重新预览；每种导出范围的实际行集合与选择完全一致；无效 DDL 在执行前被拦截。

### 第二阶段：任务和视图状态可靠

- 引入 requestId / taskId，统一异步请求过期判断、执行互斥、任务归属和事件订阅清理。
- SQL 按钮与 Monaco 快捷键共用执行锁，防止连续快捷键启动重复语句；关闭未保存草稿使用现有关闭守卫及 ConfirmDialog。
- 将表的过滤、排序、分页、列设置、选择和滚动锚点移到按 tabId 管理的状态。Data / Structure / Info 来回切换能够恢复；数据实际变化时按主键校验选择，避免指向另一行。
- 未访问的恢复标签页先显示占位内容，激活时加载。用户已经启动的任务继续运行；终端、脏编辑器和活动任务不随意卸载。
- 长任务状态统一为 queued / running / cancelling / done / partial / error / cancelled，分别展示表进度、行进度和已完成步骤；日志保留上限。
- 先接通后端取消，再显示对应 Cancel。SQL 使用驱动级取消；对比在读取批次边界退出；写入只在定义好的安全边界停止，并报告已经提交的部分。

验收：并行两个同步任务时日志不串台；较旧请求不能覆盖新视图；快速切换标签和子视图不丢状态；取消状态与真实后端行为一致。

### 第三阶段：UI 和操作路径

- **连接身份**：同库同表重名时，标签增加连接名；完整 tooltip 展示连接 / 库 / 表，对比视图始终明确源 → 目标。危险操作附近保留目标身份。
- **工作区**：延续标题栏、侧边栏、标签页、状态栏的四区布局。工具栏在最小窗口宽度下保留对象身份、主操作和运行状态；次要说明先缩短。
- **搜索**：标明当前搜索范围；统一连接、已加载库表、Redis Key 的检索入口。远端 Key 搜索使用后端游标，不以本地已加载列表冒充完整结果。
- **数据网格**：保留筛选草稿与已应用条件的区别；明确选择数量和作用范围；优化长 JSON、二进制、NULL 的展示及复制反馈。
- **Diff / Sync**：清晰显示“配置 → 对比 → 计划 → 执行”的状态；修改配置后解释为何旧结果或预览不能继续用于执行；预览区域提供执行摘要和可展开 SQL。
- **失败与空状态**：区分连接失败、加载失败、无数据、无匹配、不可比较、已取消；提供对应重试或修改条件入口。
- **键盘与视觉验收**：覆盖中文/英文、浅色/深色、色盲模式，960×640、1280×800 和高分辨率窗口；检查焦点、Esc 顶层关闭、菜单裁剪及文本溢出。

继续复用 tokens、Toolbar、Dialog、ConfirmDialog、IconButton、集中菜单和命令注册；不重复建设另一套 UI 基元。

### 第四阶段：大数据效率

1. 将整表 `Vec` API 替换为有界批次读取。导出逐批写文件；同步逐批生成并执行 INSERT；预览最多读取需要展示的 50 行，行数统计单独请求。
2. 对比使用规范化的完整主键。在两侧排序语义可证明一致的场景使用有序归并；否则以相同类型化键进行哈希分区并落临时文件，逐分区比较，避免假定跨数据库排序规则相同。
3. 比较会话提供统一主键游标和分页结果，两端从同一集合显示。明确每端读取的快照或时间范围，不把两个独立数据库描述成同一时刻的原子快照。
4. metadata 缓存按连接、库、表和版本组织；DDL、刷新、重连后失效。数据先返回，总量可显示估算或待统计，再按需精确计数。
5. 常规浏览保留页码跳转；有稳定唯一键的大表优先游标前后翻页。避免对无主键宽表默认按全部列执行昂贵排序。
6. 网格、树和 SQL 大结果引入可见行渲染；保留键盘导航、焦点、粘性列、Shift 选择和辅助技术语义。无换行行先实施，变高行单独验证。
7. 比较缓存改为按字节预算的 LRU，关闭会话清理对应缓存；预取只服务活动视图并服从全局并发限制。
8. 保留已经实现的 Monaco 延迟加载；按实际文件语言再加载语言服务。先测量主入口、xterm 和各编辑器语言的成本，再决定拆分点。
9. Redis Key 列表返回游标、已加载数量和完整性状态，支持继续加载和服务端匹配；连接按数据库隔离复用。

验收数据集：10 万与 100 万行、复合主键、稀疏键、宽 JSON、二进制、不同排序规则、20 个工作标签、1 万个树节点。

测量项：冷启动到可交互、首批行延迟、翻页查询数、精确计数次数、峰值 RSS、浏览器长任务、取消延迟、总吞吐量。先记录固定机器基线，再确定毫秒目标；不提前承诺没有测量依据的提速倍数。

硬性边界：预览不会读取整表；后台未访问标签不发起查询；导出/同步不会同时持有整表数据及整份输出；普通翻页不重复读取完整 schema 和执行两次精确 COUNT。

## 4. 已实施的修正

- 同步预览绑定请求快照及后端 15 分钟有效的单次 planId；配置或结构改变后拒绝旧计划。执行前检查源目标、表存在性、完整 DDL 和读取权限；跨引擎结构同步明确拒绝。
- 分页对比对缺失的完整主键执行跨页补查。沿用页码导航，必要时显示另一页的配对行；暂未引入统一游标会话。主键不完整、重复或两侧不一致时不再使用部分主键配对。
- 比较保留空格、NULL 类型、时区及微秒差异。大整数和精确小数在驱动和行编辑器中保持精度；非空解码失败返回错误，二进制按方言写回。
- PostgreSQL 读取真实列定义、约束、索引及常见建表 DDL，替换占位 SQL；生成列在数据导出和同步中排除。
- all / filtered / page / selected 导出范围落实到后端；SQL 标识符、字符串、布尔值及二进制按输出方言编码。CSV 支持多行字段、引号、CRLF、BOM，先验证记录再写入。导出成功后才替换目标文件。
- 对比、同步、导出统一为有背压的批次读取。整表对比采用类型化键的哈希分区，超出预算后继续分区，临时文件在结束后清理。同步预览只读取最多 50 行；mysqldump 标准输出直接写文件。
- 翻页不再重复执行两次精确 COUNT；schema 使用 15 秒、128 表上限的缓存，本地写入与 DDL 入口使缓存失效。表对比数据缓存增加约 32 MB 的序列化体积预算、LRU 和关闭会话清理。
- 未访问的标签按需挂载，已访问表子视图保留过滤、分页和滚动等组件状态；后台视图不响应前台快捷键。同名表标签显示连接名，比较标签显示两端方向。
- SQL 草稿增加关闭确认，按钮和快捷键共用执行互斥；后端返回真实结果或受影响行数，结果有行数/体积上限及持久截断提示。
- 同步进度按 taskId 隔离；失败不会再显示为成功，日志有 500 条上限。
- 新增隔离数据库测试脚本及 CI 数据库服务用例，CI 同时增加 renderer 构建。

验证：333 项前端测试、48 项 Rust 测试、类型检查和 renderer 构建通过。MySQL 9.6 / PostgreSQL 14 的两个独立集成用例通过，覆盖值往返、四种导出范围、各 100,004 行源数据的分区对比、旧计划在写入前拒绝、批量同步以及计划不可重放。这两个用例在常规 Rust 测试中标记为 ignored，由独立脚本或 CI 专门运行。

边界：列表虚拟化、真正的后端取消、统一游标会话、Redis 游标浏览、跨引擎结构转换仍属于后续增强。没有运行当前源码的桌面视觉验收或远端 CI；未提交、推送或发布。本轮没有连接或写入用户保存的数据库。
